```powershell

```

它会真实地做 7 件事，共 **68 项检查**：

| # | 验什么 | 怎么验 |
|---|---|---|
| 1 | 测试套件 | 起子进程跑 `pytest`，读真实退出码与摘要 |

- 失败会打印失败项清单，并把子进程日志留在 `.verifytmp/logs/`。
- 想跳过 pytest 快一点：`python scripts\verify_all.py --no-tests`。

## 四、跑一遍 API（手工验证）

服务起来后，另开一个 PowerShell：

### 1. 健康检查

```powershell
curl.exe http://127.0.0.1:8000/health
```

```json
{"status":"ok","schema_version":1,"db_path":"D:\\LivingMemory\\data\\yisheng.db","db_writable":null,"db_write_status":"unknown"}
```

> 默认**不做写入探测**，所以 `db_writable` 是 `null`（无法判断）。
> 想确证可写：`curl.exe "http://127.0.0.1:8000/health?probe=write"`
> → `{"db_writable":true,"db_write_status":"writable"}`。

### 2. 写入一条经历

```powershell
curl.exe -X POST http://127.0.0.1:8000/observe -H "Content-Type: application/json" -d "{\"content\":\"今天第一次把忆生跑起来了\",\"source\":\"manual\"}"
```

```json
{"id":"d390a111-e8fe-4819-ad96-cc524fcf2273","sequence":1,"recorded_at":"2026-11-07T13:17:05.403612+00:00","occurred_at":null}
```

`metadata` 是可选的**原始字符串**（不是 JSON 对象）：

- 传字符串 → `201`，原样保存、原样返回
- 传对象（`{"a":1}`）→ **422**，因为契约是"只作为字符串存储"

### 3. 按 ID 取回（完整内容）

```powershell
curl.exe http://127.0.0.1:8000/experiences/d390a111-e8fe-4819-ad96-cc524fcf2273
```

返回含 `content` 全文的完整对象。
若存储内容与 `content_sha256` 不一致 → **500 `data_integrity_error`**。

### 4. 列表（键集分页，返回**摘要**）

```powershell
curl.exe "http://127.0.0.1:8000/experiences?limit=10"
```

列表条目**不含 `content` 全文**，只有 `content_length` / `content_preview` / `content_truncated`。
要全文请用第 3 步的按 ID 查询。

有下一页时返回 `"has_more": true` 和一个 `next_cursor`，把它带上继续翻：

```powershell
curl.exe "http://127.0.0.1:8000/experiences?limit=10&cursor=<上一步的 next_cursor>"
```

> 游标合法范围 `1 .. 2^63-1`，超范围返回 **400**（不是 500）。
> 游标是不透明参数、**不是安全凭证**：构造合法游标从任意位置读取是允许的。

### 5. 验证「不可修改」

```powershell
curl.exe -X DELETE http://127.0.0.1:8000/experiences/<任意ID>
```

应当返回 **405**：

```json
{"error":"method_not_allowed","detail":"Phase 1 是 append-only 记录系统：原始经历不可修改、不可删除。"}
```

### 6. 交互式文档

浏览器打开 <http://127.0.0.1:8000/docs> ，可以直接点着调。

### 场景化测试在测什么（`test_scenarios.py`）

Phase 1 是纯记录器，不能"理解"场景。所以场景测试的含义是反过来：
**看它会不会在真实、复杂、矛盾的输入面前偷偷开始"理解"。**

| 组 | 内容 | 在证什么 |
|---|---|---|
| A 真实对话 | 整段多轮对话逐字保存；带背景/结果/元数据的完整记录；十轮对话乱序补录；重复提交同一段 | 原始性、排序按 `sequence` 而非 `occurred_at`、不去重 |
| B 与上一轮相反 | 「我怕黑」/「我不怕黑」并存；后记「推翻前一条」；改主意 5 次；连续 20 条修正后早期记录逐字节不变 | **系统拒绝调和**：两条都留、谁也不覆盖谁；无认知结构生成 |
| C 新颖场景 | 纯 emoji；Markdown+JSON；只差一字的近重复；零宽空格/NBSP；CRLF/制表符；10 万字符 emoji+中文；多语言双向文本 | 不做规范化/去重/摘要 |
| D 时间场景 | 补记多年前；预记未来 | 时间双轨互不干扰 |
| E 端到端加固 | 写→改(405)→删(405)→读回一致；20 线程并发写矛盾内容 | 不可篡改 + 并发不丢不覆盖 |

### 常见问题

**Q：测试报 `PermissionError` 或 `WinError 5`？**
A：某些受管环境（如带文件沙箱的终端）会阻止 pytest 自建临时目录。
本项目的 `tests/conftest.py` 已改为在**工作区内** `.pytest_tmp/` 建临时目录并自行清理，
不依赖 pytest 的 `tmp_path`。如果仍报错，检查当前用户对 `D:\LivingMemory\` 的写权限。

**Q：`ModuleNotFoundError: No module named 'yisheng'`？**
A：用 `python run.py` 启动（它会把 `src/` 加进 `sys.path`），
或 `pip install -e .` 安装成可编辑包。
直接 `uvicorn yisheng.main:app` 需要先安装包或设置 `PYTHONPATH=src`。

**Q：WAL 文件 `-wal` / `-shm` 是什么？**
A：SQLite WAL 模式的正常产物，会自动合并回主库。已加入 `.gitignore`，不用管。

## 八、独立模型复测（已做过，可复现）

实现完成后，邀请**独立的大参数量模型（Qwen3.8 Max）**做了**两轮**对抗性复测。

| | 第一轮（体检式） | 第二轮（对抗式，更严） |
|---|---|---|
| 结论 | **通过**，未找到违反契约的证据（40/40 检查点） | **有条件通过**：契约全符合，但发现 3 处实现缺陷 |
| 产出修改 | SQL 位置问题 → 重构 | `db_writable` 检测、`limit` 重复校验、冗余装饰器 |

两轮共让我改掉 4 个真问题（契约本身没有一条被推翻）：

1. **「SQL 只在 repository.py」不成立** → 把版本表 SQL 移进仓储层，加静态测试
2. **`db_writable` 用读操作判断，只读库上也报 true** → 改为事务内真实写入 + 回滚
   （实测：只读连接 `False`、可写连接 `True`、回滚后 `user_version` 恢复为 0、不消耗 `sequence`）
3. **`limit` 校验重复且服务层会冒 500** → 收敛到服务层单点 + 类型化异常 → 422
4. **装饰器 `status_code=405` 冗余** → 移除

复测材料：

```
.audit_qwen/adversarial_audit.py   对抗脚本
.audit_qwen/audit_report.md        复测报告
```

> 注意：另两个候选模型（DeepSeek-V4-Pro、GLM-5.3）在本会话中路由故障/中断，所以这**不是多模型共识**，
> 只是同一个外部模型的两轮独立结论。详见 `docs/README.md` 的「更大参数量模型独立复测」。
